This release updates the shared EVM deposit event for BETH and CHYPE.
The bridge change is [evm-asset-bridge#68](https://github.com/DLC-link/evm-asset-bridge/issues/68).

### Breaking change

`Deposit` gains `uint256 prevDepositBlock` as its last field.
Both `tokens::beth::mint` and `tokens::chype::mint` export this type.
Callers that construct or decode a `Deposit` must handle the new field.
The field identifies the previous deposit block for the same account.
A zero value means that no earlier deposit exists since deployment or the upgrade that adds the field.

`DEPOSIT_EVENT_TOPIC` now matches only `Deposit(bytes32,bytes,address,uint256,uint256)`:

```text
0xf3ca88974ec5963addc617fe6c0c359d7196759e318be6ab0cade940986e30e2
```

### Migration

Callers that read historical logs must also filter on the old topic:

```text
0xacaea730ea841fae3326f72a7ff746b6e06c646840526bcaf5dabee5fd887ef8
```

Declare the old four-field event in a separate `sol!` block to decode those logs.
The new `Deposit` decoder rejects logs with the old topic.
Decoding old data without checking its topic can silently produce an incorrect `prevDepositBlock` value.

### Compatibility

CBTC has no API changes in this release.
The library retains `canton-lib` v0.12.0 and `canton-api-client` 3.6.1-0.1.0.
The DAR bundle remains unchanged.
Integrators install this release with the Git tag `v0.5.0`; the crate is not published to crates.io.

### Known warning

Cargo Deny reports RUSTSEC-2026-0543 because `chrono` is unmaintained.
This release retains the dependency versions from 0.4.1.
[Issue #20](https://github.com/DLC-link/bitsafe-token-lib/issues/20) tracks remediation separately.
The maintainer accepts this warning for the compatibility release.
