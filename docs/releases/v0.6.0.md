This release removes `chrono` from the build.
RustSec marks `chrono` as unmaintained in [RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html).
The crate, `canton-lib` and `canton-api-client` now use `jiff` for time values.
[Issue #20](https://github.com/DLC-link/bitsafe-token-lib/issues/20) tracked the change.

### Breaking changes

`SendParams::execute_before` is now `Option<std::time::Duration>`.
It was `Option<chrono::Duration>`.
Pass a `std::time::Duration` at the call site, for example `Duration::from_secs(3600)`.
`send` now returns an error when the duration overflows the time range.
Before, the addition panicked.

The crate now uses `canton-lib` v0.13.0.
A project that also depends on a `canton-lib` crate must pin the same tag.
Two different pins make Cargo build two copies of the shared types, and then the types do not match.
A direct `canton-api-client` dependency must be version `3.6.1-0.1.1`.

### Wire format

`send`, `split`, `consolidate` and `batch` write `requestedAt` and `executeBefore` with a `Z` offset.
They also drop trailing zero digits, for example `2026-11-19T12:54:31.67331Z`.
Before, they wrote `2026-11-19T12:54:31.673310+00:00`.
Both forms name the same instant, and the registry and the Ledger API accept both.

### Migration

1. Change the `bitsafe-token` tag to `v0.6.0`.
2. Change every `canton-lib` tag in your `Cargo.toml` to `v0.13.0`.
3. If you set `SendParams::execute_before`, pass a `std::time::Duration`.
4. If you pin `canton-api-client` directly, require `3.6.1-0.1.1`.

### Compatibility

`canton-lib` v0.13.0 has more breaking changes in crates that this library does not use.
Its [release notes](https://github.com/DLC-link/canton-lib/releases/tag/v0.13.0) list them.
The DAR bundle remains unchanged.
Integrators install this release with the Git tag `v0.6.0`; the crate is not published to crates.io.
